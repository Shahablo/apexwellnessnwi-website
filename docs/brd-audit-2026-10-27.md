# Apex Wellness website audit and local implementation

Date: October 27, 2026

Scope: current `origin/main` at `55ef84ba2385a3926b34fab9538dfc783b53cb8e`

Release status: owner approved October 27; deployment and public verification are tracked separately and are not established by this audit

## Executive result

The BRD was useful as a checklist, but several reported failures did not match the current repository or rendered site. The local implementation keeps the existing information architecture and design while improving service-page clarity, clinic schema specificity, illustrative-image disclosure, and mobile performance. A privacy-safe measurement interface was added but remains deliberately disabled.

## Finding classification

| Reported issue | Classification | Evidence and action |
| --- | --- | --- |
| Wrong production domain | False positive | Canonicals, Open Graph URLs, sitemap, robots and Worker routes already use `https://apexwellnessnwi.com`. |
| Policy pages presented as services | False positive | The four service routes are weight management, men's hormone health, women's midlife care and hair-loss care. Policies remain in a separate policy navigation group. |
| Weak or duplicate service metadata | Partially confirmed | Titles and descriptions were already unique. The four H1s were brand-oriented rather than explicit service-and-location headings. They now name the service and Merrillville, IN. The women's midlife description now names Merrillville and the planned-care context. |
| Missing local clinic schema | Partially confirmed | Every page already had one consistent JSON-LD graph with address, phone and stable IDs. The clinic node was generic `Organization`; it is now the supported `MedicalClinic` subtype and includes the verified Google Business profile in `sameAs`. No hours, coordinates, ratings or reviews were invented. |
| Address, phone and directions missing | False positive | The confirmed address and phone were already consistent. The Merrillville page already includes an address-based Google Maps directions link and prelaunch visit guidance. |
| Inquiry form does not work | False positive in repository tests | The first-party endpoint already stores consented requests, preserves duplicates safely, rejects unsupported health fields, handles failure without false success, rate-limits abuse and exposes accessible success/error states. The full synthetic test suite passed. Production delivery still requires environment and account verification at release time. |
| Booking presented as active | False positive | The approved scheduling URL is blank and `ready` is false. The site clearly describes a request, not a confirmed booking, and rejects unsafe scheduling URLs. |
| Analytics missing | Correct, intentional safety posture | No ad pixels, analytics vendors or session replay were present. An inert first-party measurement interface is now available for future review, but it loads no vendor code, stores no identifiers and sends no requests. The external decisions needed before activation are documented in `docs/website-measurement.md`. |
| Missing FAQs or trust content | False positive | All four service pages already include useful visible FAQs, clear evaluation language, referral boundaries and prelaunch disclosures. No fake testimonials, ratings or review schema were added. |
| Canonical, sitemap, robots or internal links broken | False positive | Generated-page tests confirm unique canonicals and metadata, complete sitemap coverage, crawlable robots rules and resolving internal links. |
| Approximately 215 KB image is a mobile bottleneck | Confirmed file, not confirmed bottleneck | `behind-apex-posters-setup-2026-10-24.jpg` is 220,347 bytes (215.2 KiB), but it is lazy-loaded below the fold and Lighthouse reported no image-format savings. It was left unchanged. The actual mobile LCP element was the home shoreline hero; visually equivalent WebP recompression reduced it from 182.7 KiB to 118.5 KiB. |

## Changes made

- Replaced the four service H1s with explicit service and Merrillville headings.
- Improved the women's midlife meta description.
- Changed the shared clinic JSON-LD entity from `Organization` to `MedicalClinic` while retaining the stable `#organization` ID used by WebSite, WebPage and BlogPosting nodes.
- Added the verified Google Business profile to clinic `sameAs`.
- Kept opening hours, geographic coordinates, ratings and reviews absent because they are not verified for public use.
- Labeled generated care imagery as illustrative in alternative text.
- Added a disabled measurement adapter and a written privacy/configuration gate.
- Recompressed the actual home-page LCP image without changing its dimensions or visible composition.

## Remaining release and account work

1. Release only this exact approved implementation through the repository's normal review and deployment path.
2. At release time, verify the production form's Cloudflare D1, Turnstile and email-delivery configuration with a controlled synthetic request. Do not use medical details.
3. Leave analytics disabled until the provider, privacy basis, consent behavior, event taxonomy, retention, access and CSP domains are approved.
4. Validate the deployed canonical pages in Google Search Console and the live schema through Google's Rich Results Test after release. Those tools assess the deployed URL, not this local build.
5. Continue monitoring the home mobile LCP. The remaining delay is largely render timing rather than an oversized image request, so further changes should be based on field data rather than speculative redesign.
